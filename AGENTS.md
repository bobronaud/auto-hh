# Инструкции для Codex

Локальное однопользовательское приложение auto-hh: Playwright, TypeScript, SQLite,
Fastify и React. Без деплоя. Общение с владельцем — только по-русски; код, команды,
идентификаторы и цитаты из логов сохраняют исходный язык.

## Перед изменениями

- Прочитать относящиеся к задаче разделы [рабочей памяти](docs/PROJECT.md).
  Она содержит обязательные договорённости, причины решений и особенности hh.
- Перед архитектурными решениями также прочитать [ресёрч](docs/RESEARCH.md).
  Это исторический документ: актуальные правила находятся в рабочей памяти.
- Новые указания владельца имеют приоритет; при изменении договорённостей обновлять
  документацию. Не возвращать сознательно удалённые ограничения и функции.

## Выполнение задачи: single или team-centralized (N ≤ 4)

Перед запуском команды агентов проверить:

- Справлюсь сам за приемлемое число шагов? Да → single.
- Куски независимы друг от друга? Нет → single.
- Зависимых внешних вызовов в цепочке 5+? Да → single.

Иначе — центральный координатор и команда не более 4 агентов суммарно.

## Основные инварианты

- Цель — максимум откликов. Не добавлять LLM-скоринг и фильтры по зарплате, опыту,
  формату или географии. Маршрутизация резюме всегда имеет fallback.
- Все селекторы hh — в `src/hh/selectors.ts`, массивами кандидатов. Успех отклика
  подтверждать по DOM. На ошибки сохранять скриншоты.
- API hh не использовать. Вход только вручную, пароль не хранить.
- Лимиты считать за скользящие 24 часа. Пропуск вакансии не записывать как отклик;
  dryRun не исключает вакансию из рабочей очереди. Автоповторов неуспешных откликов нет.
- Анкету заполнять целиком или передавать человеку; тестовые задания — человеку.
  Ботам hh отвечать автоматически, живым рекрутерам — не отвечать.
- Капча: изображение → Codex → ввод, затем ручной запасной путь. Количество попыток
  и ожидание человека задаёт конфиг; отказ провайдера сразу включает ручной путь.
- Существующие промпты, разделители ответов и валидацию сохранять при замене модели.
  Письма генерировать пачками. Отбракованное письмо не сохранять.
- В откликах и сборе не добавлять пауз: ожидать состояние DOM. Особые правила для
  капчи и чатов описаны в рабочей памяти.
- **`npm run chats` отправляет сообщения даже при dryRun.** Для проверки LLM
  использовать `npm run llm:check` на синтетических данных, без обращения к hh.
- Внутри `page.evaluate` / `evaluateAll` не присваивать функции в `const`: tsx/esbuild
  добавляет недоступный в браузере `__name`. Использовать инлайн-выражения.

## Codex как провайдер приложения

`llm.provider = codex-cli`, локальный `codex exec`, вход через `codex login` с ChatGPT.
Текст: `gpt-6-luna`; изображения: `gpt-6.1-terra`; reasoning: `medium`.
Старое имя `claude-cli` поддерживается только для миграции конфигов.

Рабочие запросы LLM изолированы от разработки: отдельный временный каталог,
без пользовательского конфига и проектных инструкций, shell и веб-поиск отключены,
только финальный ответ поступает парсерам. Подробности — раздел LLM рабочей памяти.
Не переносить на Codex исторические замеры токенов и стоимости Claude.

## Проверки

`npm run typecheck` и `npm test`. Для настоящего провайдера — `npm run llm:check`
(расходует квоту, отправляет только синтетические данные). Для UI — `npm run build:ui`.
Не запускать отправляющие отклики или сообщения команды ради проверки миграции.

## Коммиты

Не добавлять атрибуцию ИИ: `Co-Authored-By`, строки о генерации Claude, Codex,
OpenAI и другими ИИ-инструментами или их варианты.

## Конфиденциальность

Не читать содержимое следующих путей, включая shell и скрипты:

- `**/.env`, `**/.env.*`, `**/*.pem`, `**/*.key`;
- `~/.ssh/**`, `~/.aws/**`, `~/.config/gcloud/**`, `~/.kube/**`;
- `~/.docker/config.json`, `~/.npmrc`, `~/.config/gh/**`, `~/.git-credentials`;
- `~/.claude.json`, `~/projects/auto-giga-recruiter/data/**`.

Не запускать `printenv` и `env` без аргументов. Наличие секретов проверять по именам
файлов и переменных без раскрытия значений. Личные данные из локального конфига,
резюме и профиля браузера не переносить в git или фикстуры. Не читать запрещённые
текущей средой файлы авторизации; для Codex использовать штатную авторизацию CLI.
