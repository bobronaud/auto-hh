# auto-hh

Автоотклики на hh.ru. Локально, для себя. Playwright гоняет настоящий браузер с вашей
сессией, API hh закрыт и не используется.

## Быстрый старт

```bash
npm install
npx playwright install chromium     # если Chromium ещё не стоит
cp config.example.json config.json  # отредактировать под своё резюме
codex login                         # вход через ChatGPT для запросов LLM
npm run doctor                      # проверка без обращения к hh
npm run login                       # откроется браузер — войти руками
npm run dev                         # сервер 127.0.0.1:3000 + UI на 5173
```

Рабочий режим — UI: `npm run dev` и открыть http://localhost:5173. Прогоны
запускаются кнопками и идут в процессе сервера, поэтому живой лог показывает их
по ходу дела.

## Как это работает

```
собрать вакансии → выдача hh → карточки → фильтр «фронтенд ли это» →
                   маршрутизация на резюме по заголовку → SQLite

откликнуться ×n  → (при letter.mode = llm сначала письма на эти же вакансии) →
                   страница вакансии → «Откликнуться» → выбор резюме → письмо →
                   отправка → подтверждение по DOM → запись в историю
```

Анкеты работодателя заполняются автоматически, если все ответы прошли проверку;
неразрешимые вопросы и тестовые задания передаются человеку. Капча распознаётся
по изображению через Codex; при ошибке провайдера или исчерпании попыток прогон
ждёт ручного ввода.

## Сопроводительные письма

Два режима, `letter.mode`:

- `static` — один текст из `letter.text` на все отклики;
- `llm` — письмо под каждую вакансию, пишется прогоном откликов автоматически.
  Вакансия, для которой письмо написать не вышло, пропускается и остаётся в очереди.

Письма можно написать и заранее — `npm run letters -- 20`;
прочитать, поправить и одобрить их можно во вкладке «очередь», отправленные видны
в «истории».

Генерация идёт через локальный авторизованный `codex exec`, провайдер `codex-cli`.
Требуется установленный [Codex CLI](https://developers.openai.com/codex/cli/) и вход
через `codex login` с ChatGPT. Отдельный API-ключ для приложения не нужен; запросы
расходуют доступную квоту аккаунта. Параметры запуска сверены с Codex CLI 0.166.0;
при ошибке неизвестного аргумента обновите CLI.

В `config.json`:

```json
"llm": {
  "provider": "codex-cli",
  "model": "gpt-6-luna",
  "imageModel": "gpt-6.1-terra",
  "reasoningEffort": "medium",
  "maxConcurrency": 1,
  "timeoutSec": 120
}
```

`gpt-6-luna` выбрана для экономичной генерации писем и ответов, `gpt-6.1-terra` —
для изображений. Имена моделей можно изменить; доступ зависит от авторизации.
Пустой `llm.model` использует `gpt-6-luna`. Письма генерируются пачками по
`letter.batchSize`, чтобы разделить контекст и накладные расходы запуска.
Исторические замеры Claude не описывают расход квоты Codex.

Старый `llm.provider: claude-cli` временно принимается с предупреждением и вызывает
Codex. Только при такой миграции пустая модель, `sonnet`/`opus`/`haiku` и `claude-*`
заменяются на `gpt-6-luna`. Остальные настройки сохраняются; файл автоматически
не переписывается. Новый конфиг лучше сразу записать как в примере выше.

`npm run llm:check` проверяет письма, анкету, ответ боту, классификацию сообщений и
изображение на синтетических данных. Команда расходует квоту, но не обращается к hh,
не читает ваши резюме и не отправляет реальные сообщения. Для изображения нужен
установленный Chromium. Если Codex запускается из файлового sandbox, ему нужны
доступ для записи служебных данных. Даже с `--ephemeral` CLI открывает
`installation_id` на запись, но прямое правило `installation_id = "write"` в CLI
0.166.0 на Linux ломает запуск sandbox (`Not a directory`); не добавляйте его.
SQLite и логи адаптер
направляет во временный каталог; запись во весь `~/.codex` не требуется.
Точная настройка — в [рабочей памяти](docs/PROJECT.md#проверка-после-перехода).
Живая проверка обеих моделей и всех перечисленных сценариев прошла 01.11.2026.
После изменения настроек её можно повторить командой `npm run llm:check`.

Вызовы приложения изолированы от интерактивного Codex: временная директория,
`read-only`, без пользовательского конфига и проектных инструкций, shell и веб-поиск
отключены. Финальный ответ отделён от служебных событий, временные файлы удаляются.
Подробности — [рабочая память](docs/PROJECT.md#llm).

## Команды

```
npm run dev              Сервер + UI вместе. Основной режим
npm run login            Ручной вход в hh.ru, один раз
npm run doctor           Конфиг, БД, сессия, очереди — без запросов к hh
npm run llm:check        Синтетическая проверка Codex, без запросов к hh
npm run collect          Сбор вакансий. Ничего не отправляет
npm run apply -- <n>     Откликнуться на n вакансий
npm run letters -- <n>   Письма заранее (не обязательно)
npm run chats [id…]      Ответы ботам hh; отправляет даже при dryRun
npm run review           Вакансии, требующие ручной работы
npm run resolve -- <id>  Пометить одну как разобранную
npm run failures         Неуспешные отклики: причины и скриншоты
npm run requeue -- <code>  Вернуть неуспешные в очередь после починки причины
npm run selectors:probe  Проверка селекторов на живом hh
npm run typecheck
npm test
```

## Что нужно знать

- **Автоотклики формально нарушают правила hh.ru.** Риск — временная или постоянная
  блокировка аккаунта. Подробности и оценка рисков — `docs/RESEARCH.md` §5.3.
- `dryRun: true` по умолчанию: пайплайн проходит целиком, но кнопка отправки не
  нажимается. Переключатель «проба / боевой режим» — в шапке UI.
- Лимиты по умолчанию (30/день, 5/час) намеренно сильно ниже потолка hh в 200 за
  скользящие 24 часа. Поднять можно, `doctor` и UI предупредят, но не запретят.
- Вход — только руками. Пароль в конфиге не хранится и не поддерживается.
- Сервер слушает только `127.0.0.1`: один POST отправляет реальные отклики от вашего
  имени, наружу такое не выставляют.

## Состояние

Всё состояние — в `data/` (в git не попадает):

```
data/session/chromium-profile/  профиль браузера = сессия hh
data/hhh.sqlite                 вакансии, письма, история откликов
data/screenshots/               скриншоты ошибок и откликов
data/probe/                     отчёты разведки селекторов
```

Резюме (`resume.*.md` и папка `resume/` с PDF) тоже вне git.
Чтобы начать с нуля — удалить `data/`.

Договорённости, подтверждённые факты о вёрстке hh и грабли, на которые уже наступили,
лежат в `AGENTS.md` и `docs/PROJECT.md` — читать перед правками.
