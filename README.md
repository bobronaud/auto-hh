# auto-hh

Автоотклики на hh.ru. Локально, для себя. Playwright гоняет настоящий браузер с вашей
сессией, API hh закрыт и не используется.

## Быстрый старт

```bash
npm install
npx playwright install chromium     # если Chromium ещё не стоит
cp config.example.json config.json  # отредактировать под своё резюме
npm run doctor                      # проверка без обращения к hh
npm run login                       # откроется браузер — войти руками
npm run dev                         # сервер 127.0.0.1:3000 + UI на 5173
```

Рабочий режим — UI: `npm run dev` и открыть http://localhost:5173. Прогоны
запускаются кнопками и идут в процессе сервера, поэтому живой лог показывает их
по ходу дела.

## Как это работает

```
собрать вакансии → выдача hh → карточки → фильтр «фронтенд ли это» →
                   маршрутизация на резюме по заголовку → SQLite

откликнуться ×n  → (при letter.mode = llm сначала письма на эти же вакансии) →
                   страница вакансии → «Откликнуться» → выбор резюме → письмо →
                   отправка → подтверждение по DOM → запись в историю
```

Вакансии с вопросами работодателя и тестовыми заданиями не откликаются автоматически:
они попадают в очередь «ручные», лимит на них не тратится. Капча останавливает прогон
и зовёт человека — автоматически она не решается никогда.

## Сопроводительные письма

Два режима, `letter.mode`:

- `static` — один текст из `letter.text` на все отклики;
- `llm` — письмо под каждую вакансию, пишется прогоном откликов автоматически.
  Вакансия, для которой письмо написать не вышло, пропускается и остаётся в очереди.

Письма можно написать и заранее — кнопкой «написать письма» или `npm run letters -- 20`;
прочитать, поправить и одобрить их можно во вкладке «очередь», отправленные видны
в «истории».

Генерация идёт через локальный авторизованный `claude -p` (подписка Claude Code,
API-ключ не нужен) пачками по `letter.batchSize` — пачка в разы экономнее по квоте,
чем письмо за вызов.

## Команды

```
npm run dev              Сервер + UI вместе. Основной режим
npm run login            Ручной вход в hh.ru, один раз
npm run doctor           Конфиг, БД, сессия, очереди — без запросов к hh
npm run collect          Сбор вакансий. Ничего не отправляет
npm run apply -- <n>     Откликнуться на n вакансий
npm run letters -- <n>   Письма заранее (не обязательно)
npm run review           Вакансии, требующие ручной работы
npm run resolve -- <id>  Пометить одну как разобранную
npm run failures         Неуспешные отклики: причины и скриншоты
npm run requeue -- <code>  Вернуть неуспешные в очередь после починки причины
npm run selectors:probe  Проверка селекторов на живом hh
npm run typecheck
```

## Что нужно знать

- **Автоотклики формально нарушают правила hh.ru.** Риск — временная или постоянная
  блокировка аккаунта. Подробности и оценка рисков — `.claude/RESEARCH.md` §5.3.
- `dryRun: true` по умолчанию: пайплайн проходит целиком, но кнопка отправки не
  нажимается. Переключатель «проба / боевой режим» — в шапке UI.
- Лимиты по умолчанию (30/день, 5/час) намеренно сильно ниже потолка hh в 200 за
  скользящие 24 часа. Поднять можно, `doctor` и UI предупредят, но не запретят.
- Вход — только руками. Пароль в конфиге не хранится и не поддерживается.
- Сервер слушает только `127.0.0.1`: один POST отправляет реальные отклики от вашего
  имени, наружу такое не выставляют.

## Состояние

Всё состояние — в `data/` (в git не попадает):

```
data/session/chromium-profile/  профиль браузера = сессия hh
data/hhh.sqlite                 вакансии, письма, история откликов
data/screenshots/               скриншоты ошибок и откликов
data/probe/                     отчёты разведки селекторов
```

Резюме (`resume.*.md` и папка `resume/` с PDF) тоже вне git.
Чтобы начать с нуля — удалить `data/`.

Договорённости, подтверждённые факты о вёрстке hh и грабли, на которые уже наступили,
лежат в `CLAUDE.md` — читать перед правками.
