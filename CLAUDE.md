# head-hunter-hunter

Локальное приложение для автооткликов на hh.ru через Playwright. Без деплоя, один пользователь.
Полный ресёрч: `.claude/RESEARCH.md` — читать перед архитектурными решениями.

## Инварианты — нарушать нельзя

1. **Все селекторы hh живут в `src/hh/selectors.ts`.** Ни одного CSS-селектора больше нигде.
   Каждый — массив кандидатов, пробуем по порядку (hh держит несколько вёрсток одновременно).
2. **Капчу не решаем.** Никаких 2captcha/anti-captcha. Увидели — остановились, позвали человека
   (`HumanNeededError`). Автоматическое решение превращает временный бан в постоянный.
3. **Пароль hh нигде не хранится.** Вход только руками через `npm run login`, сессия — в
   persistent Chromium profile. Не добавлять поля логина/пароля в конфиг.
4. **Лимит откликов — скользящее окно 24ч**, не календарные сутки. Считать только по
   `applications.applied_at`. Счётчик «сброс в полночь» рассинхронизируется с hh.
5. **`dryRun: true` — дефолт.** Финальный клик «Откликнуться» выполняется только при
   `dryRun: false`. Не менять дефолт.
6. **API hh.ru закрыт полностью** (и отклики, и поиск). Не писать код против `api.hh.ru` —
   всё через парсинг DOM.
7. **Скриншот на каждую ошибку.** Упавший селектор иначе не отладить постфактум.
8. **Никаких фиксированных пауз.** Только рандомизированные (`pause`, `randomBetween`).
9. **Вакансии с вопросами работодателя и тестовыми НЕ откликаем.** Ответы на вопросы —
   свободный текст, который должен писать человек; сгенерированный ответ хуже, чем его
   отсутствие. Такие вакансии получают статус `needs_human` и попадают в очередь ручной
   работы (`npm run review`), а не теряются.
10. **Резюме выбирает вакансия, а не конфиг, и отклик делается ВСЕГДА.** Два резюме
   (react/vue), маршрутизация в `src/scoring/resumeRouter.ts`. Vue-резюме уходит только
   когда вакансия явно про Vue; всё остальное — включая неоднозначное — идёт на react как
   фолбэк. `routeResume` никогда не возвращает «не откликаться»: цель инструмента — охват.
   Совпадение в заголовке весит в 5 раз больше, чем в теле: «Vue-разработчик, React будет
   плюсом» — это Vue-вакансия.

## Фильтры

Единственный вопрос, который фильтр вправе задавать: **фронтенд ли это вообще**.
Зарплата, годы опыта, формат работы и регион НЕ фильтруются (`area` по умолчанию пуст,
параметр в URL не уходит вовсе) — сужение по ним стоит
откликов ради критериев, которые всё равно обсуждаемы. Не добавлять такие фильтры,
даже если они кажутся разумными.

Совпадения по стеку — только по границам слов (`src/scoring/textMatch.ts`).
`includes("ui")` срабатывает внутри `build` и `guide`, `"ts"` внутри `products`,
`"vue"` внутри `value`.

## Детекторы: три правила, выведенные из ложных срабатываний

1. **Проверять видимость, а не существование.** hh держит в DOM невидимый iframe
   капчи и схлопнутые предупреждения (`hidden-resume-warning`). `firstVisibleMatch`,
   не `firstMatch`.
2. **Ограничивать область поиска.** Признаки вопросов работодателя искать внутри формы,
   а не по документу: в описании вакансии «тестовое задание» — рассказ о процессе найма.
3. **Текстовые признаки антибота — только на странице без интерфейса hh.** «DDoS-Guard»
   на живой выдаче это название компании-работодателя. См. `looksLikeHhPage`.

Общее: каждый детектор, который останавливает работу, обязан логировать сработавший
селектор. Сообщение «captcha» без имени селектора неотлаживаемо.

## Ловушки окружения

**Внутри `page.evaluate` / `evaluateAll` нельзя присваивать функции в `const`.**
tsx собирает с esbuild `keepNames`, который переписывает `const f = () => {}` в
`const f = __name(() => {}, "f")`. Колбэк сериализуется и выполняется в браузере, где
`__name` не существует — прогон падает посреди работы. Только инлайн-выражения.
В `browser.ts` есть шим-страховка, но полагаться на неё нельзя.

## Команды

```
npm run login            Ручной вход в hh.ru, один раз
npm run doctor           Проверка конфига/БД/сессии
npm run selectors:probe  Проверка селекторов на живом hh (разведка)
npm run review           Очередь вакансий, требующих ручной работы
npm run resolve -- <id>  Пометить одну как разобранную
npm run typecheck
```


### Что подтверждено на живом hh

- Выдача: `vacancy-serp__vacancy`, `serp-item__title`, пагинация ссылками `pager-page`
  (ходим по `&page=N`, кнопки «вперёд» нет)
- Модалка: `add-cover-letter` → поле письма появляется в DOM только после клика
- Дропдаун резюме: `div[role="button"]` с `[data-qa="resume-title"]`; пункты —
  радио-список `[data-qa="cell"]` в портале **вне** модалки
- `hidden-resume-warning` лежит в DOM всегда (схлопнут) — проверять только видимость
- Классы `magritte-*___hash` хешированные, опираться на них нельзя

### Что не проверено

Состояния-исключения: `success`, `limitExceeded`, `tooLongMessage`, `alreadyApplied`,
`archived`, `hasTestBadge`. Их не увидеть, пока они не наступят — при первом боевом
прогоне сверить по скриншотам.

Лимит длины письма: у поля **нет** `maxlength`, значение в конфиге (1800) — догадка.
